System overview

Factory Inventory Management System

A demo web application that shows inventory, orders, spending, demand forecasts, and reports for a factory. A Vue 3 single-page app talks to a Python FastAPI service, and the service reads all data from JSON files into memory. There is no database.

System architecture

Three tiers in one repository. The browser loads the Vue app from Vite and then calls the API directly with Axios. The API applies filters in Python lists and validates the response with Pydantic.

Tech stack

All dependencies are small and standard. There is no CSS framework, no state library, and no ORM.

Frontend

  • Vue 3 (^3.4) with the Composition API and setup()
  • vue-router 4, HTML5 history mode
  • Axios for HTTP
  • Vite 5 + @vitejs/plugin-vue for dev server and build
  • Custom SVG charts and CSS Grid; no UI library
  • Locales en.js / ja.js; currency follows the locale (USD / JPY)

Backend

  • Python ≥ 3.11, managed with uv
  • FastAPI (≥ 0.110) with automatic OpenAPI docs
  • Pydantic 2 response models
  • Uvicorn ASGI server on 0.0.0.0:8001
  • Tests: pytest + TestClient (httpx) in tests/backend/

Data and tooling

Data flow

The four global filters — Time Period, Warehouse, Category, Order Status — drive every request. This is the path a filter change takes on the Dashboard.

User changes a filterFilterBar.vue → useFilters.js

The FilterBar writes to four module-level refs (selectedPeriod, selectedLocation, selectedCategory, selectedStatus). Because the refs live outside the function, every view shares the same state.

The view reactsDashboard.vue watch([...])

A watcher on the four refs calls loadData(). It calls getCurrentFilters(), which maps the period to a month value such as 2025-09 or Q3-2025.

The API client builds the queryapi.js

Each method adds only the filters that are not all to a URLSearchParams and sends the request with Axios. The Dashboard fires four requests in parallel: summary, orders, inventory, backlog.

FastAPI filters in memorymain.py

apply_filters does case-insensitive matches on warehouse, category and status. filter_by_month checks whether the month string, or any month in the quarter, appears in order_date. Inventory has no date, so it ignores month.

Pydantic validates the responseresponse_model=List[...]

List endpoints declare a model, so a JSON record with a missing or wrong-typed field fails at response time. Summary and report endpoints return plain dicts.

Computed properties derive the UIDashboard.vue

Raw arrays go into refs (allOrders, inventoryItems). Everything on screen — status counts, category totals, order trends, top products, revenue goal — is a computed over those refs. Currency and labels come from useI18n.

Shared state and conventions

  • Filters — singleton refs in useFilters.js; no Pinia or Vuex.
  • Locale — useI18n.js keeps the locale in localStorage and falls back to English keys.
  • User — useAuth.js is a mock profile with locale-aware fields; there is no login.
  • Styling — global styles in App.vue; slate palette (#0f172a, #64748b, #e2e8f0); status colours green / blue / yellow / red.
  • Charts — hand-built SVG inside the views, no chart library.
  • Revenue goals — $800K for a single month, $9.6M year-to-date when all months are selected.

Things to know

State is process-local. Data lives in Python lists loaded at import. A restart resets everything, and two server processes never share state.
Filters are string matches. filter_by_month uses substring checks on order_date; a month like 2025-1 would over-match. Warehouse matches are exact and case-sensitive.
Client calls endpoints that do not exist. api.js defines tasks and purchase-order calls (POST /api/tasks, POST /api/purchase-orders, …) but main.py has no such routes; the Tasks modal catches the error and keeps tasks in memory in the browser.
CORS allows every origin with credentials. Fine for a local demo; tighten before any deployment.
API base URL is hard-coded to http://localhost:8001/api in api.js; there is no environment switch.
Tests cover the backend only (tests/backend/): dashboard, inventory, misc endpoints. There are no frontend tests.
